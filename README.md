# Browser Guard

Локальная платформа контроля **Browser Use 0.13.14**: FastAPI, SQLite, React/TypeScript. Задачи, правила, решения, подтверждения и результаты доступны через панель. Git локальный, публикации нет.

## Запуск на Windows

Проверено с Python 3.13, Node.js 25 и установленным Chrome. Путь `C:\src\browser-guard` выбран вне OneDrive, подмодулей нет.

```powershell
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.lock.txt
npm.cmd --prefix frontend ci
npm.cmd --prefix frontend run build
Copy-Item .env.example .env  # только при первой установке!
.\start.ps1
```

Панель: **http://127.0.0.1:8765**. В существующей установке `.env` уже заполнен: не заменяйте его примером. Ключи `GROQ_API_KEY`, `ZAI_API_KEY`, `OPENROUTER_API_KEY`, `GOOGLE_API_KEY` хранятся только в backend и исключены из Git. Агент получает отдельный профиль Chrome. После смены моделей перезапускайте сервис.

## Модели и бюджет

Бюджет API **$0**: фиксированный список бесплатных моделей и адресов, без платного fallback. Groq и Google требуют отметки о подтверждённом бесплатном плане. Временный 429 вызывает ограниченное ожидание того же endpoint; дневной или длительный лимит останавливает запрос.

| Роль | Проверенный маршрут |
|---|---|
| Калибровка | установленный Codex CLI, `gpt-6.1-sol` |
| Контрольный агент | Google `gemini-2.5-flash` Free Tier |
| Текстовая оценка | Groq `openai/gpt-oss-120b`; отдельно проверен `openai/gpt-oss-20b` |
| Другие кандидаты | Z.ai `glm-4.7-flash`, визуальный `glm-4.6v-flash` |
| Только синтетическая проба | OpenRouter `nvidia/nemotron-3.5-super-vl:free` |

Текущая установка по умолчанию использует Codex для калибровки: отдельный временный каталог, read-only sandbox, отключённые инструменты/приложения/поиск, без ключей API в окружении. Это клиент облачной модели по существующей подписке, **не офлайн-модель**. Запуски отмечены `calibration`, API-контроль — отдельно. OpenRouter отключён для произвольных пользовательских задач из-за ограничений передачи данных.

## Подключение

`guard/runner.py` создаёт `Agent(task=..., tools=GuardedTools(...), browser=...)`. Защищённый `act` получает реальный вызов и наблюдение из **той же BrowserSession**, запрашивает `/api/decide` и вызывает исходный `Tools.act` только после разрешения. Отдельного CDP-наблюдателя или системного фильтра нет. Другому типу агента потребуется собственное проверенное подключение к этому контракту.

Контекст: прямая цель, инструмент/параметры, адрес и свойства элемента/формы, до 12000 знаков наблюдения, пять последних действий, при необходимости снимок. Скрытые рассуждения агента не требуются. Страница недоверенная. Модель извлекает признаки, правила в `guard/policies/base.json` определяют итог. Пользовательские ограничения редактируются в панели. Явное поручение разрешает соответствующую отправку; подтверждение оставлено для значимой неоднозначности и выбранных пользователем правил.

Перед исполнением проверяются активность задачи, версия/хеш правил и отпечаток цели действия. Согласие одноразовое и ограничено по времени. Запрет возвращается агенту с причиной для перепланирования. Отмена не откатывает выполненный эффект; потеря записи результата не повторяет вызов.

## Проверки

```powershell
.venv\Scripts\python.exe -m pytest -q
.venv\Scripts\python.exe tools/ui_smoke.py
.venv\Scripts\python.exe -m tools.browser_smoke
.venv\Scripts\python.exe -m tools.semantic_checks --provider codex
# Короткий контроль на бесплатном API:
.venv\Scripts\python.exe -m tools.semantic_checks --provider groq
```

UI-пробе нужен сервис. `browser_smoke` проверяет настоящий исполнитель с тестовым анализатором. `semantic_checks` проверяет настоящую модель на готовых предложениях. Это разные уровни проверки. Автономные опыты через панель запускает `tools/run_cycle.py`, например `--case read --tag my-read`; `--video` сохраняет реальную запись UI.

Для скрытой формы отдельно запустите `.venv\Scripts\python.exe -m uvicorn guard.lab_sink:app --host 127.0.0.1 --port 8767`. Все данные вымышленные, приёмник локальный. Готовые пилоты и результаты — **`docs/verification.md`**, измерения — `artifacts/pilot-summary.json`, видео — `artifacts/video/browser-guard-demo.mp4`. Профили и полные журналы — `.data/` и `artifacts/runs/` вне Git. Массовые бенчмарки отложены до просмотра пользователем.

## Интерфейс после аудита

Панель переработана вокруг выбранной задачи: история и поиск слева, цель/результат/действия справа. Общие KPI убраны; модели конкретного запуска отделены от текущих настроек. На телефоне история раскрывается кнопкой, контекст доступен с клавиатуры и закрывается Escape. В журнале есть поиск, фильтр и страницы; разрешение и фактическое исполнение показываются отдельно.

Исследование и макеты: [аудит](docs/ui-audit.md), [дизайн-решения и источники](docs/design/decisions.md), [интерактивный макет](docs/design/browser-guard-concept.html). Макет использует вымышленные данные; приложение — сохранённые реальные запуски. Снимки текущей панели — `artifacts/ui-redesign/`.

`tools/ui_redesign_checks.py` проверяет сохранённую историю и изолированные браузерные состояния, не запускает модели. Пройдены 7 базовых UI-проб и 11 проверок редизайна. Видео полного агентского цикла записано до обновления внешнего вида и сохраняется как исходное свидетельство работы.

## Границы текущей версии

Одна проверенная интеграция; модель данных допускает несколько агентов. Непрозрачные `evaluate` и файловые инструменты исключены. Автономный JavaScript и обход `GuardedTools` не контролируются. Истинность каждого итогового ответа не проверяется. Скрытые секреты определяются эвристически по полям и типам; неизвестная схема может её обойти. `off` сохраняет сбор контекста/журнал: это не полностью неинструментированный агент. Единичные пилоты не дают общей оценки устойчивости.

Внешние компоненты: [Browser Use](https://docs.browser-use.com/open-source/customize/tools/add), [WebArena-Verified](https://servicenow.github.io/webarena-verified/v1.2.3/), [DoomArena](https://github.com/ServiceNow/DoomArena). Авторская часть — слой контроля, правила, сервис, интеграция, панель и проверочные сценарии.
