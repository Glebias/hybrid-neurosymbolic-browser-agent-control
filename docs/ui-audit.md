# Аудит интерфейса Browser Guard

Проверено 02.11.2026: исходные `frontend/src/main.tsx` и `style.css`, сохранённые снимки и живой интерфейс `http://127.0.0.1:8765` в Chrome 1440×1000, 760, 390 и 320 CSS px. Задачи агенту не запускались, API-модели не вызывались, данные сервиса не изменялись. Это аудит исходного интерфейса до текущего редизайна.

## Что выглядит шаблонно

Это оценка композиции, а не доказательство, что код написан ИИ. Сочетание тёмного сайдбара, больших белых KPI-карточек, пастельного текста 8 px и рекламных строк «Прозрачное управление», «Решения под вашим контролем», «Цель → проверка → действие → объяснимый результат» похоже на универсальную SaaS-заготовку. Для контроля агента эти элементы расходуют место, которое нужно текущему адресу, действию и результату. Декоративная стрелка у некликабельного имени Browser Use создаёт ложное ожидание перехода.

Убрать рекламные надписи и дублирование; сохранить спокойный фон, один основной акцент, смысловые цвета с текстом и ясную иерархию кнопок. Главная кнопка формулирует действие, вторичные не конкурируют с ней. [GOV.UK Button](https://design-system.service.gov.uk/components/button/).

## Что сохранить

- Различение «разрешено» и «действительно выполнено» — основа правильного доверия к интерфейсу.
- Причину блока, идентификаторы правил и возможность посмотреть исходный контекст.
- Раздельные задачи, правила, подтверждения и журнал; их не нужно сливать в один бесконечный чат.
- Метку калибровки Codex и отдельные API-результаты; можно сделать компактнее, но не прятать смысл.
- Видимый отказ/отмена/неизвестный результат, а не только счастливый путь.

## Минимальная приёмка после правок

1. На 1440×900 выбранная задача, режим и последний шаг понятны без прокрутки рекламной шапки.
2. На 320/390/760 px доступны прошлые задачи и состояние агента; документ не шире viewport.
3. Все основные действия выполняются клавиатурой, фокус виден, модальное окно закрывается Escape и возвращает фокус.
4. Обычный текст контрастен ≥4,5:1; измерять реальные пары цветов, не проверять «на глаз».
5. Проверить длинную цель, много действий, ошибку, заблокированный и подтверждённый вызов, отсутствие связи. Поля и кнопки не перекрываются; результат не маскирует ошибку исполнения.
6. UI-пробы не должны запускать платные/бесплатные агентские модели: достаточно существующих данных и изолированного тестового backend.


## Повторная проверка после основного редизайна

Read-only Chrome, 02.11.2026, 1440/760/390/320 px. Ни одного запроса POST/PUT/DELETE, агентские модели не вызывались, ошибок JavaScript нет. Измерения: `artifacts/ui-audit-recheck.json`.

Исправлены основные проблемы исходной версии: компактная рабочая шапка вместо рекламных KPI, читаемый текст, доступные история задач и агент на мобильных ширинах, видимый focus textarea, настоящий статус потери связи, более точные тексты политики и учебного примера. Native dialog получает фокус, Escape закрывает его и возвращает на исходную кнопку. Фоновое приложение не доступно по Tab; переход фокуса в browser chrome допустим и не считается выходом на фон.

Разделение актуальной конфигурации и истории работает: на выбранном старом API-запуске раскрытие показывает Gemini/Groq, тогда как текущие настройки запуска — Codex. Сохранено различие ALLOW и фактического исполнения.

Оставшиеся замечания, переданные основному агенту:

- В первой новой сборке вкладка журнала ещё расширяла документ до 764 px на 320/390 px и до 770 px на 760 px. Остальные три вкладки укладывались во viewport. Сама таблица корректно находилась в overflow:auto; наружный контейнер требовал локализации переполнения. Повторить проверку после соответствующего CSS-исправления.
- Метка «Правила» у шага с model_skipped вводит в заблуждение в режиме off: там контроль отключён. Для neural подпись также должна отражать выбранный режим.
- При assessment=null и model_skipped=false модель могла вызываться неуспешно. Инспектору нельзя в этом случае утверждать «Модель не вызывалась»; следует сообщать об отсутствии полученной оценки.

Это проверка перечисленных сценариев, а не заявление о полном соответствии WCAG.


## Финальная перепроверка исправлений

Все четыре оставшихся замечания закрыты на новой сборке:

- Журнал: documentWidth равен viewport на 320, 390, 760 и 1440 px. Таблица прокручивается только внутри своего контейнера на узких экранах.
- Мобильная история: кнопка «История задач» доступна; список изначально свёрнут и появляется после нажатия, агент остаётся видимым. Так результат занимает более высокое положение без потери доступа к истории.
- Реальный сохранённый запуск off: каждый шаг подписан «Контроль отключён», а инспектор сообщает, что модель не вызывалась из-за отключённого контроля. ALLOW и «Выполнено» отображаются отдельно.
- Сбой получения оценки: браузерная проверка с подменой только ответов GET (assessment=null, model_skipped=false, MODEL_UNAVAILABLE) показала корректный текст «Оценку модели получить не удалось». Данные backend и модели не затрагивались; это проверка UI-ветки, не новый реальный отказ API.

Измерения сохранены в `artifacts/ui-audit-final.json`, предыдущий JSON дополнен ссылкой на финальную проверку. Ошибок JavaScript и мутационных запросов нет. Дополнительных блокирующих замечаний в проверенном объёме не осталось.
